## API integration and complete White Label compared

| Decision | API integration | Complete White Label |
| --- | --- | --- |
| Customer interface | Your existing app or bot | Branded Web and Telegram applications |
| Development work | Your developers implement the agreed integration | The platform's branded interfaces are configured |
| Project scope | Defined API capabilities and provider flows | Customer interfaces plus agreed operational tools |
| Best starting point | Existing product and technical team | Existing audience and a need for a branded application |

An API agreement defines the available capabilities. A consumer demo is useful for reviewing the experience, while technical documentation and integration access are arranged as part of the agreed process.

## Capabilities to discuss

Project scoping can cover USDT funding, card programme integration, customer onboarding flows, transaction information and the operational tools your team needs. The exact endpoints, supported operations, networks and provider flows must be confirmed against current documentation before implementation.

Virtual or physical cards, Visa or Mastercard availability, Apple Pay and Google Pay support depend on the selected programme and eligible customer countries.

## What to send before a technical discussion

1. Your product URL or a short description of your bot or application.
2. Target customer countries and your business's operating location.
3. Your reachable audience and expected active card users.
4. An estimate of monthly funding volume.
5. The features you need and who will perform the integration.

This gives the team enough information to assess product fit and prepare a relevant technical discussion.

## How an integration moves forward

After the initial qualification, the parties agree on scope, programme availability and commercial terms. The technical team then confirms documentation, onboarding requirements, testing arrangements, support responsibilities and the launch process.

Avoid assuming that every feature visible in the consumer application is automatically available through every API configuration. Confirm the required user journeys explicitly: onboarding, funding, card access, transaction visibility and support.
